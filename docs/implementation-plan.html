00决策与执行原则

0.1 已确认的产品决策

决策项结论
Focus / Habits两个都做
数据迁移数据简单、使用天数少，无需复杂迁移；允许清库重建作为兜底（仍会在升级前本地备份）

平台Android only
排除智能捕捉、语音、云同步、拍照扫描、小组件、农历、多端

0.2 执行纪律（每个阶段都必须遵守）

  • 改动前：对要修改的 symbol 跑 GitNexus impact(direction:"upstream")，HIGH/CRITICAL 先停下报告；UNKNOWN 视为未决，用文本搜索复核。
  • 提交前：跑 detect_changes(scope:"all")，partial/truncated 不算干净，需重跑。
  • 只改 full 分支；opensource 分支在发布前不动。
  • 每次改 schema 前：本地导出一次 JSON 备份（设置→导出）或 adb pull DB。
  • 安装 APK 前先 adb uninstall 旧包。
  • 每阶段结束：flutter analyze 0 error + 模拟器回归清单通过。

01目标架构

保留现有分层，不引入 Clean Architecture 全套。新增一个"虚拟实例查询层"作为读侧核心。

UI (ConsumerWidget)
   │ watch
Providers：taskList · calendar · section · focus · habit · tag · theme
   │
TaskDateQueryEngine（新增）  ← 虚拟实例 + occurrence 叠加 + 缓存
   │
TaskRepository（扩展 occurrence / focus / habit 查询）
   │
AppDatabase (sqflite v9) + AppPrefs

读写分离：读走虚拟实例；写只落"定义 + 例外（occurrence）"。

核心领域模型

class TaskOccurrence {          // 读侧视图对象，不落库
  final Task task;              // 模板或普通任务
  final DateTime day;           // 该次日期（当天 00:00）
  final String state;           // pending | done | skipped
  bool get isDone => state == 'done';
  bool get isSkipped => state == 'skipped';
}

02数据模型变更（v5 → v9）

迁移策略 数据简单，采用"尽力转换 + 失败可重置"：升级时把已物化的重复实例（recurrence_id IS NOT NULL）折算成 occurrence 后删除；若折算异常，只清空实例行、保留模板任务，用户手动补即可。升级前先本地导出备份。

2.1 新增表

RecurrenceCalculator 正确语义（示例）

// weekly 且指定了周几：从 current 之后找最近的匹配星期（按 interval 周对齐）
DateTime nextWeekly(DateTime cur, Set<int> weekdays, int interval) {
  for (var i = 1; i <= 7 * interval + 7; i++) {
    final d = cur.add(Duration(days: i));
    if (weekdays.contains(d.weekday)) return d;
  }
  return cur.add(Duration(days: 7 * interval));
}
// monthly
DateTime nextMonthly(DateTime cur, int interval, String mode, int? day, int? weekIndex) {
  final m = DateTime(cur.year, cur.month + interval);
  switch (mode) {
    case 'day':       return DateTime(m.year, m.month, day ?? cur.day); // 越界自动 clamp
    case 'last':      return DateTime(m.year, m.month + 1, 0);
    case 'week':      return nthWeekday(m.year, m.month, cur.weekday, weekIndex!);
    case 'week_last': return lastWeekday(m.year, m.month, cur.weekday);
  }
}

查询引擎

Future<List<TaskOccurrence>> query(DateTime from, DateTime to) async {
  final templates = await repo.getRecurringTemplates();          // 带 rule
  final singles   = await repo.getNonRecurringInRange(from, to);
  final occMap    = await repo.getOccurrencesInRange(from, to); // (taskId, ymd)->state
  final out = <TaskOccurrence>[];
  for (final t in templates) {
    for (final day in RecurrenceCalculator.daysBetween(t.rule!, from, to)) {
      out.add(TaskOccurrence(t, day, occMap[t.id!]?[ymd(day)] ?? 'pending'));
    }
  }
  for (final t in singles) {
    out.add(TaskOccurrence(t, dayOf(t.startDate!), occMap[t.id!]?[ymd(t.startDate!)] ?? t.status));
  }
  return out;
}

12每阶段 Definition of Done

阶段完成标准
Phase 0重复实例虚拟化；完成/跳过只写 occurrence；task 表行数不随天数增长；重写后的 recurrence 全部单元测试通过；旧修复（含撤销/恢复）无回退
Phase 1分区（逾期/今天/未来/今日完成）可折叠可调序；筛选与分区混合切换；右滑 5 动作 + 左滑 Star；全部可撤销
Phase 2月历点与任务一致、点日期出列表；专注 Timer/Stopwatch、暂停、休息、记录、后台恢复准确
Phase 3习惯打卡与连续天数正确；统计范围切换一致；重复任务未来 7 天提醒真机准时；稍后提醒可用
Phase 4动画/性能打磨完成；full 与 opensource 两包均可构建并安装；真机回归全过；开源版已推送 Release
